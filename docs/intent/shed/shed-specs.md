# Shed Ledger specs

Prefix `SHED`. Design: `shed-design.md`. The problems served are in brackets. A minute is a Unix minute, `floor(nowMs / 60000)` for a `tier` call and the packet's own minute for a report; `nowMs` is Unix milliseconds from the caller.

- [x] **SHED-001** [1]: When `tier(nowMs, tier)` is given AMBER or RED and the previous call's tier was GREEN, the Shed Ledger shall open an AMBER event at the call's minute, and when it is given RED and the previous call's tier was GREEN or AMBER, it shall open a RED event at that minute, treating the tier before the first call as GREEN; the previous call's tier is updated even when SHED-002 opens no event.
- [x] **SHED-002** [1]: The Shed Ledger shall open no event when `tier` repeats or lowers the previous tier, and when the tier rises into an event's tier before that event's end minute (SHED-011), it shall open no new event and shall clear that event's end, so the same event continues.
- [x] **SHED-003** [1]: If `tier` is called with a `nowMs` that is not finite or is earlier than the previous call's `nowMs`, with a tier other than GREEN, AMBER or RED, or with a label other than LIVE, REPLAY or SIMULATED, then the Shed Ledger shall throw RangeError and leave its tier, time, events and label unchanged.
- [x] **SHED-004** [1, 2]: When `report(packet)` is called, the Shed Ledger shall store the packet with its power state (payload flags bit 0: 0 is power off, 1 is power on) and return true only if its type is OK (0) or REPORT (2), it is not marked `duplicate`, its minute is an integer and payload level is an integer from 1 to 6, and otherwise shall store nothing and return false.
- [x] **SHED-005** [1, 2]: For one level and one event, the Shed Ledger shall count the level as observed when at least 3 distinct senders, a sender being the pair (key set id, member byte), have stored reports of it, power on or off, with a packet minute inside the event's window (SHED-011), and as reported without power when at least 3 distinct senders have stored power-off reports of it inside that window, counting each sender once however many reports it sent.
- [x] **SHED-006** [1, 2]: `odds(level, tier, nowMs)` for tier AMBER or RED shall return `{ p, cuts, events, label }`, where `events` is the number of events of that tier with an end minute and `end minute × 60000 ≤ nowMs` in which the level is observed (SHED-005), `cuts` is how many of those count the level as reported without power, `p = (cuts + 1) / (events + 2)`, and `label` follows SHED-012.
- [x] **SHED-007** [1, 2]: While no event of the requested tier has ended by `nowMs` with the level observed in it, `odds` shall return `p` exactly 0.5, `cuts` 0 and `events` 0, the result callers display as "no data yet".
- [x] **SHED-008** [1, 2]: If `odds` is called with a level that is not an integer from 1 to 6, a tier other than AMBER or RED, or a `nowMs` that is not finite, then it shall throw RangeError.
- [x] **SHED-009** [1, 2]: For the same `tier` calls and the same set of reports, `odds` shall return the same result whatever order the reports arrive in, before, between or after the `tier` calls, including reports that arrive after their event has ended.
- [x] **SHED-010** [1, 2]: `createShedLedger({ label })` shall throw RangeError for a label other than LIVE, REPLAY or SIMULATED, and the Shed Ledger shall read no clock and use no randomness, taking every time from its caller.
- [x] **SHED-011** [1, 2]: When `tier` lowers the tier from at or above an event's tier to below it, the Shed Ledger shall set that event's end minute to the call's minute plus 10; the event's window is the packet minutes `m` with event minute ≤ `m` < end minute, and an event with no end has no upper bound and is open.
- [x] **SHED-012** [1, 2]: `tier` and `report` shall each take an optional label (LIVE, REPLAY or SIMULATED, default the creation label), `report` shall throw RangeError for any other label, and `odds` shall return as `label` the weakest of the creation label and the labels of every accepted `tier` call and stored report, SIMULATED being weaker than REPLAY and REPLAY weaker than LIVE.
