# Adapter factory specs

Prefix `ADAPT-POLICY`. Design: `policy-design.md`. The problems served are in brackets.

- [ ] **ADAPT-POLICY-001** [1, 2, 3, 4, 5, 7, 8, 9]: `createAdapters(policy, script)` shall return new adapter objects with ids `p01`, `p02`, `p03`, `p04`, `p05`, `p07`, `p08` and `p09`, each with fresh private state, and shall throw a RangeError for a policy other than `'directorate'` or `'stratum'`.
- [ ] **ADAPT-POLICY-002** [1, 2, 3, 4, 5, 7, 8, 9]: Each adapter shall declare exactly the `reads` and `writes` given for its id in the rung 3 table of `adapters-design.md`, and shall run under the kernel's checked mode without a write violation for the whole seven-day scenario under either policy.
- [ ] **ADAPT-POLICY-003** [1, 2, 3, 4, 5, 7, 8, 9]: Given the same policy, script, initial world and seed, two sets of adapters from `createAdapters` run by the kernel shall produce identical final worlds and identical metrics, and shall draw randomness only from the stream passed to `step`.
- [ ] **ADAPT-POLICY-004** [1, 2, 3, 4, 5, 7, 8, 9]: Every adapter's `metric` shall return a finite value labelled SIMULATED, leave the world unchanged, and return 0 for a share whose denominator is still 0.
- [ ] **ADAPT-POLICY-005** [2, 3, 5, 9]: The adapters shall name sector claims `s00` to `s23` with debt 0, take Fair Share allocations as `allocate(supply, claims).shares`, write every allocation with exactly the keys `s00` to `s23`, compute a sector's power demand as `people × BASE_KW / 1000` MW and its life floor as `people × LIFE_KW / 1000` MW, and size the cooling and pump pools as their nominal capacities times the grid's served fraction.
- [ ] **ADAPT-POLICY-006** [1, 3, 5, 9]: The adapters shall compute every served fraction as `demand > 0 ? min(1, max(0, granted / demand)) : 1`, read sector `s`'s share as `alloc.<good>[sectorId(s)]`, and take a sector's ventilation served fraction as the served fraction of its power over its life floor.
- [ ] **ADAPT-POLICY-007** [1, 2, 3, 4, 5, 7, 8, 9]: In a checked seven-day run under either policy, a snapshot of the world before and after each adapter's step shall differ only in the sub-fields the "Who writes what" table of `adapters-design.md` gives that adapter, with inbox and ledger changes limited to the stated appends and removals.
- [ ] **ADAPT-POLICY-008** [1, 4, 5, 7, 9]: Each adapter shall build its world-dependent state on its first `step` from the world passed in, with p01's previous served fractions taken from the initial `alloc.power`, tier history before `t = 0` counted as GREEN, and p05's flooded flags set to `isFlooded(sumpLevel, false)`.
